# לקוח חדש: מהשאלון ועד אתר באוויר

כל זוג הוא תיקייה אחת ב־`clients/<slug>/`, ופרויקט Vercel אחד שמצביע על אותו ריפו עם `CLIENT=<slug>`.
הקוד משותף לכולם. כשמשפרים משהו, כל הלקוחות מקבלים אותו בפריסה הבאה שלהם.

## 1. השאלון ללקוח (מה לבקש)

**חובה**
- השם שלו ושלה (או שלו ושלו, שלה ושלה) וכתובת האתר שירצו. מי מזמין את האתר (הוא מקבל את הניהול) ולמי הוא מיועד.
- מתי התחילו להיות ביחד (תאריך).
- איזה חלקים רוצים באתר (ראו טבלה למטה), או אחת מהחבילות: **מלא**, **מכתבים ותמונות**, **רק תמונות**.

**מומלץ**
- מתי ואיפה הכירו ("בחתונה של רוני").
- יום הולדת של מי שמקבל/ת את האתר (לועזי, ואם רוצים גם עברי).
- מספר טלפון של המזמין (לכפתור "אני צריכה אותך" בוואטסאפ ובשיחה).
- 10–40 תמונות, ולכל אחת משפט קצר (מצחיק או מרגש, לא תיאור).
- כינויים (5–20).
- אם רוצים מכתבים: מכתבים/פתקים/שירים שכתבו אחד לשנייה. אחד נפתח כל יום.
- חיית מחמד וירטואלית: **שרקן, חתול, כלבלב או ארנבון**, ושם מוצע.
- הסיפור שלהם בכמה נקודות (לציר הזמן), מקומות שהיו בהם (למפה), דברים שעוד רוצים לעשות.
- בדיחות פרטיות, מילים שהמציאו, שובר/הבטחה שרוצים לתת.
- פלייליסט ספוטיפיי משותף (קישור).
- ייצוא צ׳אט וואטסאפ (רק אם רוצים "ספר" ו"היום לפני שנה"; Claude כותב מהם פרקים).

## 3. בניית התיקייה (את זה Claude עושה)

1. מעתיקים את `clients/_template` ל־`clients/<slug>`. ה־slug הוא הכתובת: אותיות קטנות באנגלית, ספרות ומקף, למשל `noa-yoav`.
2. `profile.json`: `slug` (אותו שם כמו התיקייה), כותרת, שמות, מגדר (`"m"`/`"f"`) וטלפון של המזמין.
   - **הכניסה היא בשם הפרטי:** השם של המזמין פותח את עמוד הניהול, והשם שלה פותח את האתר שלה. אפשר להוסיף כתיבים נוספים: `"login": { "admin": ["yoav"], "partner": ["noa"] }`.
3. `index.ts`: תאריכים, חבילה (`presets.full` / `presets.lettersAndPhotos` / `presets.photosOnly`) והחיה.
4. תמונות: `python3 scripts/add-photos.py <slug> <תיקייה-עם-התמונות>`. הסקריפט מכין את הקבצים ומדפיס את הרשימה ל־`content/photos.ts`. כותבים לכל תמונה כיתוב.
5. `content/index.ts`: כל השאר. הדוגמה המלאה היא `clients/demo/content/`. כל הטקסטים נכתבים בקול של המזמין, לפי המגדר של שניהם.
6. בודקים:
   ```bash
   CLIENT=<slug> npm run dev       # http://localhost:5173/<slug>/ (?at=2026-11-05T08:00 לראות יום אחר)
   npm run build                    # בונה את כל הזוגות
   npm run check:leaks
   ```

## 4. העלאה לאוויר

**אין מה לעשות בוורסל ללקוח חדש.** פרויקט Vercel אחד מגיש את כל הזוגות, וכל זוג נמצא בכתובת משלו:

`https://<הפרויקט>.vercel.app/<slug>/`

כש־Claude מוסיף את התיקייה וממזג לענף הראשי, Vercel בונה מחדש לבד, ותוך דקה הכתובת עובדת.

מוסרים למזמין:
- הקישור
- "נכנסים עם השם הפרטי: אתה עם שלך, היא עם שלה"
- "בעמוד הניהול מחכה לך כרטיס התראות. פעם אחת מתקינים את ntfy ומדביקים את הערוץ"

### הקמה חד־פעמית (פעם אחת בחיים)
1. Vercel → Add New → Project → הריפו הזה. בלי הגדרות מיוחדות.
2. Storage → Upstash for Redis → Connect. מסד אחד לכל הזוגות, וכל זוג נשמר תחת `<slug>:`.
3. Settings → Environment Variables: `SESSION_SECRET` (מחרוזת אקראית ארוכה). זהו.
4. **הדמו לכל המתעניינים:** `https://<הפרויקט>.vercel.app/demo/`, או פשוט הכתובת הראשית. נכנסים בלי שם ובלי סיסמה. רואים את האתר שלה ואת עמוד הניהול שלו, עם מתג למעלה, ואי אפשר לשנות או לשמור כלום.

**כמה לקוחות נכנסים במסד החינמי?** 256MB. בממוצע זוג תופס כמה מגה, כולל התמונות והציורים שהיא שומרת לחיה. כשמתקרבים לגבול, רואים את זה בכרטיס "המקום שלנו" בעמוד הניהול, ואז עוברים לתוכנית בתשלום של Upstash (סנטים לחודש).

**חשוב:** תוכנית Hobby של Vercel היא לשימוש לא מסחרי. כשמוכרים, צריך את Pro (בערך 20$ לחודש), אחד לכל הזוגות.

## 5. אחרי המסירה

**האתר עובד לתמיד, בלי טיפול.** כשנגמרים הפתקים, התמונות, פרקי הספר או הפגישות ביומן, כל יום חוזר אחד ישן ("זוכרת את זה?", "מהארכיון שלנו", "פרק לקרוא שוב"). כל הספירות (ימים ביחד, ימי נישואים, ימי הולדת, "היום לפני שנה", הגיל של החיה) ממשיכות לרוץ לבד. ההתחברות מתחדשת בכל כניסה, ופעם ביום Vercel מעיר את המסד (`crons` ב־`vercel.json`) כדי ש־Upstash לא ירדים אותו אחרי חודש בלי כניסות.

- תוכן חדש (מכתבים, פרקים, תמונות): מוסיפים בתיקייה של הלקוח ופורסים.
- המזמין יכול לבד: הודעה מיוחדת ליום, פתק נוסף, ברכה, פגישה הבאה, עיצוב, גיבוי, מתנות לחיה.
- "להעתיק ל־Claude" בעמוד הפגישות: מה שהיא כתבה ביומן נהיה פרק בספר.
